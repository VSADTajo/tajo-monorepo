# Implementation Plan: Scheduled Path Cleanup Jobs

**Branch**: `004-path-cleanup-jobs` | **Date**: 2026-03-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/004-path-cleanup-jobs/spec.md`

## Summary

Add dynamic, database-persisted cron jobs that automatically delete files with specified extensions from configured directory paths. Each path in the Paths & Files panel gets a clock icon to create/view/toggle/edit/delete its cleanup job. Backend uses `@nestjs/schedule` + `SchedulerRegistry` for runtime scheduling; jobs survive restarts by loading from PostgreSQL on startup. Paths overview response is extended to include cleanup job status per path.

## Technical Context

**Language/Version**: TypeScript 5.7+ / Node.js >= 22
**Primary Dependencies**: NestJS 11, @nestjs/cqrs 11, TypeORM 0.3, @nestjs/schedule (new — to install), React + TanStack Query (frontend)
**Storage**: PostgreSQL 16 — new `cleanup_jobs` table
**Testing**: Jest + Supertest + Testcontainers
**Target Platform**: Linux server (Docker), browser (React frontend)
**Project Type**: Web application (NestJS backend + React frontend)
**Performance Goals**: Jobs execute within 30s of scheduled time; paths-overview loads in <500ms including cleanup job data
**Constraints**: One job per path; minimum 5-minute interval; non-recursive deletion (direct children only)
**Scale/Scope**: Low volume — typical deployments have 5–50 configured paths, each with at most one job

**`cleanup-job.entity.ts`** — extends `BaseAuditEntity`, implements `IValidable`. Columns: `directoryPath` (varchar, unique), `extensions` (text[]), `frequency` (varchar enum), `isActive` (boolean, default true), `lastExecutedAt` (timestamptz, nullable), `lastExecutionResult` (jsonb, nullable), `nextExecutionAt` (timestamptz, nullable). `validate()` delegates to `FileExtensionsValueObject` and validates `frequency` is a valid enum value.

**`file-extensions.value-object.ts`** — validates array has ≥1 item; normalizes each to lowercase with leading dot; deduplicates. Throws `EntityError` if empty after normalization.

**`cleanup-job-repository.port.ts`** — abstract class `ICleanupJobRepository` with methods: `findAll`, `findAllActive`, `findById`, `findByDirectoryPath`, `findByDirectoryPaths`, `create`, `update`, `delete`.

**`cleanup-scheduler.port.ts`** — abstract class `ICleanupScheduler` with methods: `scheduleJob(job: CleanupJob): void`, `unscheduleJob(jobId: string): void`, `rescheduleJob(job: CleanupJob): void`, `getNextExecution(frequency: CleanupFrequency): Date`, `isScheduled(jobId: string): boolean`.

**`cleanup-job.result.ts`** — `CleanupJobResult` with all entity fields as readonly properties.

### Application Layer

**`cleanup-job.commands.ts`** — four command+handler pairs:
- `CreateCleanupJobCommand` / `CreateCleanupJobHandler`: validate entity, check no duplicate path (ApiError 409), save, call `ICleanupScheduler.scheduleJob()`, return result
- `UpdateCleanupJobCommand` / `UpdateCleanupJobHandler`: find by id (ApiError 404), update extensions/frequency, validate, call `rescheduleJob()`, update `nextExecutionAt`, save, return result
- `ToggleCleanupJobCommand` / `ToggleCleanupJobHandler`: find by id, set `isActive`, if activating → `scheduleJob()` + compute `nextExecutionAt`; if deactivating → `unscheduleJob()` + null `nextExecutionAt`, save, return result
- `DeleteCleanupJobCommand` / `DeleteCleanupJobHandler`: find by id (ApiError 404), call `unscheduleJob()` if scheduled, delete from repo, return `{ deletedId }`

**`cleanup-job.queries.ts`** — three query+handler pairs:
- `GetCleanupJobByIdQuery` / `GetCleanupJobByIdHandler`
- `GetCleanupJobByPathQuery` / `GetCleanupJobByPathHandler`
- `ListCleanupJobsQuery` / `ListCleanupJobsHandler`

**`file.queries.ts` (modify `ListPathsOverviewHandler`)** — inject `ICleanupJobRepository`; after building `pathMap`, call `findByDirectoryPaths(absolutePaths)` and attach job info to each path entry.

**`cleanup-job.mappers.ts`** — `CreateCleanupJobMapper`, `UpdateCleanupJobMapper`, `ToggleCleanupJobMapper`, `DeleteCleanupJobMapper`, `GetCleanupJobMapper`.

### Infrastructure Layer

**`cleanup-job.repository.ts`** — TypeORM implementation of `ICleanupJobRepository`. Standard pattern: `@InjectRepository(CleanupJob)`, try/catch wrapping with `RepositoryError`.

**`cleanup-scheduler.service.ts`** — Implements `ICleanupScheduler` + `OnModuleInit`. Key responsibilities:
1. `onModuleInit()`: load all active jobs from `ICleanupJobRepository`, call `scheduleJob()` for each
2. `scheduleJob(job)`: create `new CronJob(cronExpression, callback)`, `schedulerRegistry.addCronJob(job.id, cronJob)`, `cronJob.start()`
3. `unscheduleJob(id)`: `schedulerRegistry.deleteCronJob(id)` (safe — check `isScheduled` first)
4. `getNextExecution(frequency)`: create a `CronJob` with the expression, call `nextDate().toJSDate()`, destroy it
5. Execution callback: list files in directory (via `IFileStorageService.list()`), filter by extensions, delete each via `IFileStorageService.delete()`, update `lastExecutedAt` + `lastExecutionResult` on the entity via `ICleanupJobRepository.update()`

**`infrastructure.module.ts` (modify)** — add `CleanupJob` to `TypeOrmModule.forFeature([...])`, bind `ICleanupJobRepository → CleanupJobRepository`, bind `ICleanupScheduler → CleanupSchedulerService`.
