# Implementation Plan: CSV File Provider for FlowCast Historical Data Ingestion

**Branch**: `003-csv-file-provider` | **Date**: 2026-04-21 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/003-csv-file-provider/spec.md`

## Summary

Add a new `CSV_FILE` provider type to ms-model-api that parses Tagus_FlowCast.csv multi-block files containing historical observed hydrological data from ~220 stations. The provider follows the existing provider pattern: download via ms-sftp-api, parse to NormalizedTimeSeriesResult[], publish to RabbitMQ. No changes to ms-predictions-api — the `*.historical` parameter naming matches the existing historical filter.

## Technical Context

**Language/Version**: TypeScript 5.7+ on Node.js >= 22  
**Primary Dependencies**: NestJS 11, @nestjs/cqrs 11, TypeORM 0.3, axios  
**Storage**: PostgreSQL 16 (existing tables only — no new migrations)  
**Testing**: Jest + Supertest + Testcontainers  
**Target Platform**: Linux server (Docker container)  
**Project Type**: NestJS microservice (hexagonal architecture + CQRS)  
**Performance Goals**: Parse ~230 station blocks (~113K lines) within 60 seconds  
**Constraints**: File encoding ISO-8859-1 (use native TextDecoder), max file size ~200MB  
**Scale/Scope**: ~220 stations, ~960 events per Q block, ~240 events per Precip block
