# Implementation Plan: Paths & Files Manager

**Branch**: `003-paths-schema-manager` | **Date**: 2026-03-09 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/003-paths-schema-manager/spec.md`

## Summary

Add a "Paths & Files" section to the frontend admin panel that shows all configured directory paths (from SFTP users and mapping schemas), their files (lazy-loaded on expand), their assigned parsing schemas, and allows toggling schema activation inline.

Backend adds one new aggregation endpoint (`GET /api/files/paths-overview`) to the existing `FileController`. Frontend adds a new page and supporting files following existing patterns.

## Implementation Details

### Backend: New query handler

**File**: `src/app/application/queries/file.queries.ts`

New `ListPathsOverviewHandler`:
- Injects: `ISftpUserRepository`, `IMappingSchemaRepository`, `StorageConfigService`
- Fetches all SFTP users + all mapping schemas in parallel
- Builds a `Map<string, MappingSchema>` keyed by absolute `directoryPath`
- Collects all unique paths from both sources (deduplicated by absolute/normalized key)
- Converts absolute paths to relative: `path.relative(basePath, absolutePath)` — if result starts with `..`, marks `canListFiles: false`
- For paths without `/` prefix (SFTP users): treats as already relative
- Returns sorted by `displayPath`

**Cache**: Register in `CACHE_REGISTRY` with key `paths-overview` and short TTL (30s) — invalidated when schemas or SFTP users change (handled by existing command handlers via `cacheService.delByPattern`)

Actually: since the existing `ToggleMappingSchemaHandler` already invalidates schema caches, and the overview depends on schemas, the overview cache should use a pattern that gets cleared. Add to `CACHE_REGISTRY`:

```typescript
CACHE_REGISTRY.set('ListPathsOverviewQuery', { ttl: 30, key: () => 'paths:overview' });
```

And add `PathsCacheKeys` to `cache-config.registry.ts`.

### Backend: New endpoint

**File**: `src/app/api/controllers/file.controller.ts`

```
GET /api/files/paths-overview
@ApiEndpoint({ summary: 'List all paths with schema assignments', ... })
→ CachingQueryBus.execute(new ListPathsOverviewQuery())
→ ListPathsOverviewMapper.toResponseDto(result)
```

### Frontend: New page

**File**: `frontend/src/pages/PathsManagerPage.tsx`

- `PathCard` component: expandable row, lazy loads files on click, shows schema badge + toggle
- `PathsManagerPage`: fetches overview, renders list of `PathCard`, handles loading/error states
- Toggle reuses existing `useToggleSchema` hook from `useSchemaMutations.ts`
- On toggle: invalidates both `['paths-overview']` and `['mapping-schemas']`
- Download: `<a href={getDownloadUrl(file.path)} download>` — direct browser download

### Frontend: Query invalidation on toggle

When a schema is toggled, the `paths-overview` query must also be invalidated so the badge updates. Modify `useToggleSchema` in `useSchemaMutations.ts` to also invalidate `['paths-overview']`.
